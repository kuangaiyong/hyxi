# 回复按原帖结构呈现 + 采集完整性提示

> 采集侧的故障（回复采不全、层级被压平）见
> `docs/fixes/2026-09-13-facebook-thread-incomplete.md`。两者一起交付：
> 呈现的前提是采得到、层级对。

## 分诊

- **修复**：回复采不全、回复的回复被压平 —— 现有行为与预期不符
- **新功能**：回复的回复怎么呈现、原帖显示多少条要不要标出来 —— 结果页的外部可见行为变了

## 我读到的需求

1. [描述] 所有主贴下的评论与回复都要采全，包括回复的回复
2. [描述] 回复下面还有回复的，呈现方式要让用户觉得采得完整，**最好和原帖结构一样**
3. [我的推断] 用户判断「完整」的依据是原帖上那个评论数；只要层级对、数字对得上，
   就不会再怀疑少采
4. [我的推断] 原帖结构 = Facebook 浮层里的样子：评论一层，回复缩进挂在所回复的那条下，
   回复的回复再缩进一层（真站实测最深见到第 3 层）

## 设计

每条决策：**选了什么 — 为什么 — 如果错了代价是什么**。

### D1. 补齐：信息流里点开浮层就地收割，找不到入口的留到本轮最后按固定链接补

- **选**：点卡片上的折叠 → 浮层 → 在浮层里展开、提取、关闭。卡片上没有可点的入口（或点了
  没弹浮层）而原帖数对不上的，本轮信息流滚完后逐条打开固定链接补齐
- **为什么**：真站实测点「查看更多回答」弹的就是浮层，关闭后信息流原样 —— 这是真实用户的
  动作，只发浮层那几个请求。固定链接是整页加载，重得多，只当兜底
- **错了代价**：浮层关不掉会卡住信息流（v1.11.0 那次整轮只剩一条帖子的事故）。所以关闭
  逐级退：关闭按钮 → Esc → 后退 → 重新载入信息流（丢掉滚动进度，日志明说）；
  且提取信息流前先确认不在浮层上（D8）
- **兜底出错只跳过那一条**（代码评审补）：固定链接打不开时整轮照样完整，日志说明跳过；
  站点拒绝访问（限流）与浏览器没了照样停下
- **等评论到了再收**（代码评审补）：浮层内容是 XHR 取的，一出现主贴就收的话折叠还没渲染，
  会被记成「整串读完」（D4）而再也不补。收割前等浮层里 article 条数稳定 1.5 秒（最多 10 秒）。
  等到头还是只有主贴：卡片上也没露评论的当作原帖确实看不到评论，收空串；卡片上露过的不收，
  留给固定链接补。找开着的浮层一律要求可见，藏起来的旧浮层不许接走点击
- **信息流里的收割出错只放弃这一串**（代码评审补）：收割到一半页面调用失败（例如浮层里点了什么触发
  整页跳转、页面上下文被销毁）就关掉浮层接着采，原帖数对不上的留给固定链接补。冒到 main 的话首轮一条都还
  没交出去就整轮硬失败，而这条主贴每轮都会再点、再失败；浏览器没了照样停

### D2. 层级：链接定「是评论还是回复」，缩进 / DOM 嵌套定「回复的是谁」

- **选**：有无 `reply_comment_id` 区分评论与回复。回复的直接父贴：DOM 上嵌在某条评论
  article 里的直接认它（fixture 与 2026-08-04 实测过的卡片形态）；否则取文档顺序里
  **前面最近一条缩进更小的**（栈算法，浮层形态）。最后拿 `comment_id` 校验顶层评论，
  对不上以链接为准挂到那条顶层评论下，并计数进日志。**链接指向的顶层评论没采到时挂主贴**
  （代码评审补）：按缩进猜的那条已知是错的，挂上去就是「回复挂错人」
- **为什么**：浮层里回复是兄弟节点，只有缩进和链接看得出层级。aria-label 写得最明白
  （「X 回复了 Y 的回复」），但随账号界面语言变，只进日志不当判据
- **错了代价**：Facebook 改成用内层元素缩进时 left 失效 → 回复退化成统一挂在顶层评论下
  （第 2 层）。仍比现在（全挂主贴）准，且链接校验保证不会挂错顶层评论；日志里
  「层级与链接不一致 N 处」能暴露它

### D3. 原帖评论数：采集时读评论按钮上的数字，存 `posts.site_comment_count`

- **选**：主贴这一层（不在任何评论 article 里）的 `[role=button]`，文字是纯数字、
  aria-label 含「评论 / 回答 / comment / answer / reactie」。新增可空 INTEGER 列，
  UPDATE 用 `COALESCE(?, 原值)` —— 这一轮读不到不许冲掉上一轮读到的
- **为什么**：这是用户在原帖上看到的数字，「已采 X / 原帖 Y」的 Y 只能在采集时拿到；
  它同时决定要不要打开浮层（D4），能少开很多次
- **错了代价**：Facebook 的数字含被隐藏 / 删除的评论时会一直标黄（误报「可能不全」）。
  文案写「可能不全」并在悬停说明里讲清；读不到数字时退回「卡片上有折叠就打开」
- **每轮都刷新**（代码评审补）：增量运行时老主贴指纹见过就不再输出，原帖数只靠帖子带的话
  停在第一次采到时 —— 涨了之后这一轮又没补齐，照样「已采 6 · 原帖 6」不标黄。所以脚本把本轮
  读到的每条主贴的数单独放进输出的 `thread_counts`，runner 在 upsert 之后按 message_id 写回

### D4. 要不要打开浮层：原帖数 > 已有数

- **选**：`site_comment_count > max(本轮卡片上已采到的, 库里已有的)` 才打开。库里已有数由
  Python 按主贴 message_id 算好随 job 下发（`known_comment_counts`），全量重跑时清空
  （与 `known_fingerprints` 同一处）。**库里已有 = max(子树条数, `harvested_site_count`)**
  （代码评审补）：后者是上一次「浮层里折叠点到一个不剩、每条评论的时间都取到了」时原帖显示的数
- **为什么**：日常增量跑时老帖评论没变就不必每轮再开一遍浮层；全量重跑要全部重来。
  只数子树的话，被「最相关」藏掉、删了没减数的评论永远对不上，这类帖子每轮增量都要再开一遍；
  拿 `site_comment_count` 顶又会让上一轮没补成（到了时限、浮层没弹）的帖子再也不补
- **错了代价**：库里已有数偏大（例如包含挂错的行）会让该补的帖子在增量时被跳过；
  「读完」判宽了（例如折叠点了没反应却算读完）同样跳过，直到原帖数再涨。
  全量重跑不受影响，且完整性提示会把它标黄

### D5. 采集时限：接近任务超时主动收尾，按退出码 2 交出已采到的

- **选**：`CollectorRunner` 在 job 里下发 `deadline_at`（任务超时前留 3 分钟余量）；脚本在
  每次开浮层、每次滚动、每条兜底补齐、每次 hover 取时间之前检查，过点即停，输出 `complete: false` +
  说明原因的 `stop_reason`，退出码 2。hover 那一处是代码评审补的：一条最多等好几秒，
  几百条回复的一串能把余量耗光；没取到时间的照样输出，下一轮按 message_id 归并回同一行。
  限流退让同理（代码评审补）：`gotoPage` 照 Retry-After 最多睡 5 分钟，比余量还长 —— 要睡过时限就不睡，
  当场按拒绝访问停下
- **为什么**：补齐让一轮变长，而现在超时是直接杀进程 —— 交接文件还没写，**整轮一条都不入库**
- **错了代价**：余量不够（写交接文件 + 关浏览器超过 3 分钟）仍会被杀，实测写文件是秒级；
  到点时任务标为失败，要调大 `TWEAKERS_TASK_TIMEOUT_MINUTES` 后重跑

### D6. 结果页：回复全部展开、按层级缩进，第 2 层起标「回复 某某」，头部「已采 X · 原帖 Y」

- **选**：去掉「只显示前 3 条」；缩进随层级递增；第 1 层评论标「N 条回复」；第 2 层起行头写
  「回复 <父贴作者>」（从父指针现算，不存新字段）；`X < Y` 标黄
- **为什么**：G1 口径；「回复 某某」正是原帖浮层里 aria-label 表达的关系
- **错了代价**：热帖卡片很长 —— 用户已知悉并选择全部展开

### D7. 采集器不改账号的评论排序

- **选**：不点排序菜单，只把浮层里当前排序的名称记进日志
- **为什么**：菜单里写明「评论排序方式将应用于 Facebook」，是账号级设置，采集器悄悄改用户
  账号的设置越界
- **错了代价**：排序是「最相关」时疑似垃圾评论采不到，这类帖子会标黄。账号设成哪种由用户定

### D8. 信息流提取排除浮层里的 article

- **选**：只取不在 `[role=dialog]` 里的顶层 article
- **为什么**：浮层残留会被当成一条新主贴（无 id、无时间的重复行，本库已有 2 条）
- **错了代价**：几乎没有 —— 信息流本身不在 dialog 里（实测）；万一改版放进去了，
  「第一批零帖子即硬失败」会拦住，不会静默

### D9. fixture 的评论部分按 2026-09-13 真站结构重写

- **选**：9004 改成「卡片 1 条 + 查看更多回答 + 评论数 6」，点击后 pushState + 浮层，浮层内容
  由 fixture 服务器接口返回（像真站的 XHR，服务器记下被请求几次）；新增 9005「评论数 3、
  卡片 1 条、没有折叠」，走固定链接兜底；9001 的就地折叠保留（v1.11.2 真站跑出过就地展开）
- **为什么**：旧 fixture 里「回复嵌在父评论里」「详情是整页跳转」两条都与真站不符，
  测试一直在替错误的假设作证
- **错了代价**：fixture 仍然是假设，所以交付前必须跑一轮真站（任务 12）

## 规格

### R1 回复层级与原帖一致

- **S1** WHEN 浮层里依次是评论 C1（缩进 a）、回复 R1（缩进 b>a）、R2 与 R3（缩进 c>b）、
  R4（缩进 b）、评论 C2（缩进 a）THEN 入库 C1、C2 的父贴是主贴且 `reply_level=1`；
  R1、R4 的父贴是 C1 且为 2；R2、R3 的父贴是 R1 且为 3
- **S2** WHEN 卡片里回复 article 嵌在评论 article 内 THEN 回复的父贴是那条评论，`reply_level=2`
- **S3** WHEN 按缩进算出的顶层评论与链接 `comment_id` 指向的不一致 THEN 以链接为准挂到那条
  顶层评论下，`reply_level=2`
- **S3b** WHEN 链接 `comment_id` 指向的顶层评论不在浮层里 THEN 这条回复挂主贴（`reply_level=1`），
  它自己的回复仍挂它
- **S4** WHEN 全量重跑遇到一条历史上被压平的回复 THEN 它在库里的 `parent_fingerprint` 与
  `reply_level` 被改写成正确值，`seq` / `translation` / `sentiment_at` 不变

### R2 评论与回复采全

- **S1** WHEN 卡片上的折叠文案是「查看更多回答」THEN 它会被点开
- **S2** WHEN 点开后弹出浮层 THEN 浮层里的全部评论与回复入库；浮层被关闭；URL 回到信息流；
  后续主贴与第二屏照常采到
- **S2b** WHEN 浮层地址不带末尾斜杠（`/permalink/<id>`，2026-09-15 真站实测）THEN 照样认作这条主贴的浮层就地收割，
  不退到固定链接
- **S3** WHEN 卡片上没有折叠按钮而原帖评论数 > 已采到 THEN 本轮信息流滚完后打开它的固定链接补齐
- **S4（拒绝路径）** WHEN 浮层用关闭按钮 / Esc / 后退都关不掉 THEN 重新载入信息流并在日志说明；
  **不得在浮层上提取信息流**
- **S5（拒绝路径）** WHEN 浮层开着时提取信息流 THEN 浮层里的 article 不计入，
  本轮不产生没有 message_id 的主贴
- **S6（拒绝路径）** WHEN 某条主贴的固定链接打不开（网络类失败）THEN 跳过这一条并在日志说明，
  整轮 `complete=true`
- **S6b（拒绝路径）** WHEN 信息流里点开的浮层收割到一半页面调用失败 THEN 放弃这一串并在日志说明、关掉浮层，
  其余主贴与固定链接补齐照常，整轮 `complete=true`
- **S7（拒绝路径）** WHEN 补齐时站点回 403 / 429 / 503 且退让一次后仍拒绝 THEN 停止采集，退出码 2，
  已采到的入库
- **S8** WHEN 浮层先出主贴、评论 2 秒后才到 THEN 等评论到了再收割，整串入库
- **S8b** WHEN 浮层里评论一直没加载出来、卡片上露过评论 THEN 这一串不收，信息流滚完后按固定链接补齐
- **S8c** WHEN 原帖显示有评论、卡片上和浮层里却一条都看不到 THEN 收空串并记成读完，原帖数不涨就不再打开
- **S9** WHEN 页面上藏着一个关掉后没拿走的旧浮层 THEN 展开折叠与关浮层都作用在开着的那个上
- **S10** WHEN 点完折叠后这条主贴自己的评论没多、信息流却多了一条 THEN 判为「没变化」，本批不再点它

### R3 原帖评论数

- **S1** WHEN 卡片上评论按钮文字为「6」THEN 该主贴 `site_comment_count=6`
- **S2** WHEN 再次采集读不到数字 THEN 库里原值保留，不写成空
- **S3** WHEN 调 `/posts` THEN 主贴带 `site_comment_count`，回复一律为 `null`
- **S4** WHEN 增量运行时一条已入库的主贴原帖数从 6 变成 7 THEN 库里 `site_comment_count=7`
  （它本身不作为新帖输出）

### R4 按需打开浮层

- **S1** WHEN 增量运行且原帖评论数 ≤ 库里已有数 THEN 不打开浮层（fixture 服务器浮层接口 0 次请求）
- **S2** WHEN 全量重跑 THEN 忽略库里已有数，数字对不上的都打开
- **S3** WHEN 一条主贴整串读完过、原帖数仍比采到的多，且原帖数没再变 THEN 增量运行不再打开；
  原帖数涨了 THEN 再打开
- **S4** WHEN 上一轮没把整串读完（到了时限没开、浮层里折叠没点完、有评论没取到时间）THEN 下一轮增量照样打开

### R5 时限收尾

- **S1** WHEN `deadline_at` 已过 THEN 脚本不再开浮层、不再滚动、不做兜底补齐、不再 hover 取时间，输出
  `complete=false` 且 `stop_reason` 含「时限」，退出码 2；已采到的帖子入库
- **S2（拒绝路径）** WHEN 被限流、Retry-After 要求的等待会越过 `deadline_at` THEN 不等待、不再请求，立即停止，
  退出码 2，已采到的入库

### R6 结果页呈现

- **S1** WHEN 打开一条带嵌套回复的主贴 THEN 所有回复默认可见（渲染条数 = 接口子树条数），
  缩进随层级递增
- **S2** WHEN 回复层级 ≥ 2 THEN 行头显示「回复 <父贴作者>」
- **S3** WHEN `site_comment_count=Y` 且子树条数 `X < Y` THEN 头部显示「已采 X · 原帖 Y」并标黄，
  悬停说明「可能不全」
- **S4** WHEN `X ≥ Y` THEN 不标黄
- **S5** WHEN `site_comment_count` 为空 THEN 只显示「💬 X 条回复」（现状）

## 非目标

- **不点排序菜单改账号设置**（D7）
- **不存「回复了谁」的文字**：从父指针现算，存一份就是双写
- **不改指纹算法**：历史数据全部失配、已翻译的要重新付费
- **不写历史数据迁移去修层级**：层级只有重采才知道，靠全量重跑（R1-S4）
- **Tweakers 不动**：论坛楼层没有「回复的回复」这一层结构
