# 点导航菜单「没有任何反应」：懒加载 chunk 拿不到，而 vue-router 静默吞掉

## 现象

用户访问 `http://127.0.0.1:8000/tasks`，页面出现
【访问被拒绝：请在「LLM 配置」页填写与后端一致的服务访问密钥】，
**但点击【LLM 配置】菜单没有任何反应**。

## 复现

**稳定复现，100%。** 复刻单端口部署形态（后端同时供页面和 API，即便携包的样子）：

```powershell
cd frontend; npm run build
Copy-Item -Recurse frontend\dist web        # mount_frontend() 认项目根的 web/
cd backend; ..\.venv\Scripts\python.exe -m uvicorn main:app --port 8000
```

浏览器打开 `/tasks` 让页面加载完，然后**把 ConfigView 的 chunk 文件从磁盘上挪走**
（= 服务端换了一份构建），再点【LLM 配置】。修复前实测：

```
点击后 URL : http://127.0.0.1:8000/tasks     ← 没动
页面标题   : 任务管理                          ← 没变
侧栏高亮项 : 📋 任务管理                       ← 没变
页面内容   : 还是任务管理                       ← 没变
失败的请求 : ConfigView-COPQgcTM.js -> 404
控制台     : TypeError: Failed to fetch dynamically imported module
```

**界面上零反馈。**用户点了一下，什么都没发生 —— 与报告逐字对应。

## 根因

两处叠加，缺一不成立：

1. **路由全是懒加载**：`frontend/src/router/index.ts` 里每条都是
   `() => import('@/views/XxxView.vue')`，Vite 构建出的 chunk 文件名**带内容哈希**
   （`ConfigView-COPQgcTM.js`）。换一份构建就是一批全新的名字，旧名字全部 404。
2. **vue-router 对导航失败不做任何界面反馈**：`import()` reject 之后导航被中止，
   `router.onError` 没注册就是**静默吞掉** —— 不抛到页面上，不改 URL，不改视图。

### 这一次是怎么触发的

`127.0.0.1:8000` 这个端口先后被两个不同的服务占用过：

1. 先是**便携包**（`build/out/HYXi-1.10.1-win64`）在跑，它托管自己那份 `web/`，
   用户的标签页从它这里加载了 SPA。包的 `.env` 里只有 `TWEAKERS_SECRET_KEY`，
   **没有 `TWEAKERS_API_KEY`**，所以接口不鉴权，一切正常。
2. 我为了验证新代码，把 8000 端口上的进程杀掉换成了**源码开发态后端**。
   它从项目根 `.env` 读到 `TWEAKERS_API_KEY`，**要鉴权**；而它在开发态
   （`web/` 不存在）**根本不托管前端**，`/assets/*` 一律 404。
3. 用户那个标签页里的 SPA 还活着。它的 API 调用打到新后端 → **401 → 那条 toast**；
   点任何一个还没加载过的路由 → chunk 404 → **静默失败**。

### 为什么以前没出问题

因为它只在**「页面还开着，服务端换了一份构建」**时才触发：

- 源码开发态永远不会 —— Vite 直出源码模块，服务重启会整页 reload
- 便携包**首次**安装也不会 —— 页面和 chunk 来自同一份构建

**但它绝不只是开发机上换端口才会碰到。**每个用户**升级便携包时不硬刷新**，
走的就是完全相同的这条路：旧页面 + 新构建 = 所有没访问过的路由全部点不动，
而且一个字的提示都没有。这是一条真实的、面向所有用户的产品缺陷。

## 修法

`frontend/src/router/index.ts` 注册 `router.onError`，只改这一处：

- 认出 dynamic import 失败（三种浏览器措辞都收）
- **整页刷到目标路径** —— 那会重新拿 `index.html`，里面是新的 chunk 名。
  这正是「升级了但没硬刷新」那条路的正解，用户什么都不用做
- **只自动刷一次**（`sessionStorage` 打标记，`afterEach` 成功到站即清）。
  刷完还拿不到就不是「换了构建」而是服务端真的没了 —— 再刷就是无限循环，
  页面一直闪比原来的静默失败更糟。这时给一条可见的、说得出下一步的提示
- `sessionStorage` 的读写都包了 try/catch：隐私模式下它会直接抛，
  不能让错误处理器自己把页面搞挂

## 回归证据

`frontend/e2e/stale_bundle_navigation.js`（真 Chrome、真后端、真的把 chunk 文件挪走，
无 mock）。四条断言分别钉住不同的事，不是同一个条件的几种说法：

```
# 红（修复前，3/4 失败）
  ❌ ① 自动整页刷到了目标路径      {"导航序列":[],"最终URL":".../tasks"}
  ❌ ② 刷完仍拿不到时界面上有可见提示  控制台: Failed to fetch dynamically imported module
  ✅ ③ 只自动刷一次，不许无限循环     （空转通过：它防的是修复本身失控）
  ❌ ④ 绝不是「什么都没发生」

# 绿（修复后）
  ✅ ① ✅ ② ✅ ③ ✅ ④        全部通过
```

后端全量：`394 passed`（本次未改后端，确认没被带坏）。

## 反思：为什么会出现这样的问题

### 一、我把一个端口当成了自己的

`start.ps1` 明明白白告诉过我 **「端口 8000 已在监听（PID 9964），跳过启动，直接验证」**。
我为了让新代码生效，直接把它杀了 —— **从没问过那上面跑的是什么**。
那很可能就是用户正在用的便携包。

教训：**别人机器上已经在监听的端口不是我的**。要换服务先说清「8000 上现在有个进程，
是不是你在跑的便携包？我要停掉它」，而不是自己决定。这条已写进 CLAUDE.md。

### 二、我让用户去验证，却没说清「哪个地址是哪个东西」

我上一轮的回复里给了两个地址（后端 8000 / 前端 5173），**没有说 8000 在开发态
根本不提供页面**。用户去访问 8000 是完全合理的行为。

教训：给验证地址时要说清每个地址背后是什么、以及**同一个端口号在开发态和便携包里
是两种完全不同的东西**。

### 三、真正的产品教训：整个测试体系看不见「陈旧标签页」

三个 E2E 脚本全都是「打开一个全新页面 → 操作 → 断言」。**没有任何一条覆盖
「页面已经开着，服务端变了」**。而这恰恰是升级场景的常态。

这一类失败的共同特征是**静默**：不崩溃、不报错、不变化，测试和用户都看不出来。
`stale_bundle_navigation.js` 是这一类的第一条覆盖。

### 四、「什么都不发生」是最坏的失败形态

比报错更糟：用户不知道该重试、该刷新、还是该找人。这次是懒加载 chunk，
但同一个形状在别处也成立 —— 任何 `await` 失败后不改变界面状态的地方都是。
已作为一条常驻红线写进 CLAUDE.md。

## 顺带发现（看到但没动）

- **同一个东西有三个名字。**401 提示说「**服务访问密钥**」，
  便携包《使用说明》说「**接口密钥**」，而 LLM 配置页上那个输入框标签是
  「**Access Key**」（英文）。用户照着提示去找「服务访问密钥」，页面上并不存在。
- **那个框还在首屏之外。**LLM 配置页从上到下是「LLM API 配置（API Key / Base URL /
  Model Name）」「多模态模型配置（API Key / Base URL / Model Name）」，
  用户要填的 Access Key 排在这两块**下面**，1280×800 视口下要滚动才看得到 ——
  而首屏那两个「API Key」是完全不同的东西，极易填错。
- **那条 401 toast 是常驻的（duration 0）**，导航之后仍留在屏幕上。用户即使照做了，
  红色的「访问被拒绝」也还挂在右上角，看不出自己做对没有。
- **开发态访问 `http://127.0.0.1:8000/tasks` 回的是 `404 {"detail":"Not Found"}`**，
  没有任何提示告诉人「页面在 5173」。

以上四条都属于「同一段用户旅程里的其它缺陷」，但根因各不相同，按最小改动原则
本次没有动，留给用户决定是否一并修。
