# v1.11.0 发版前评审：五个视角并行找、独立反驳者核实

## 怎么跑的

对 `git diff v1.10.1`（含工作区）+ 未跟踪的新文件，起 5 个互相看不见的评审代理，
各盯一个视角：采集脚本、存储层、后端 API 与安全、前端行为、测试与文档是否名副其实。
每条 medium 以上的发现再交给一个**以反驳为目标**的核实者。

**没跑完**：会话额度在中途耗尽，6 个代理失败（4 个核实者 + 后端/前端各一个核实者 +
**「测试与文档」那一整路视角**）。已完成 5 个（4 个视角 + 1 个核实），
产出 8 条发现。「测试与文档」这一路由我自己补做（见文末）。

## 核实者推翻的部分（保留在这里，免得下次又照着错的走）

S1 的提出者附带说「按根因②，seq 17/18 的父指针 `5de87dc32c712b76` 应当在别名表里，
修复文档自相矛盾」。核实者以只读方式查了真实库：**该指纹在 `post_aliases` 里既不是
fingerprint 也不是 canonical，`posts` 表里也没有**，且代码里没有任何
`DELETE FROM post_aliases`。所以
`docs/fixes/2026-09-09-facebook-reply-undercollection.md` 里「父贴的真实身份无从得知」
这句**是对的**，不要按那条建议去改。核实者同时把 S1 从 medium 下调为 low：
它不是本次引入的回归（v1.10.1 自己在任意一次重启时就会做同样的提升），
且本地真实库里当前命中数为 0 —— 但机制成立、会改变用户可见结果，所以照修。

## 未修的一条：B1

被 `merge_duplicate_posts()` / `drop_empty_posts()` 提成主贴的**评论**，
`message_id` 还是它的 comment_id，而 `_post_url()` 只凭 `reply_level == 0` 判断「这是
主贴」，于是拼出 `/groups/{gid}/permalink/{comment_id}/` —— 点开不是那条回复，也不是
它的主贴。评审在开发库上实测：65 条带链接的主贴里有 2 条是这样（就是 seq 17/18）。

**为什么这次不修**：根治要让「显示在树根」和「它本身是回复」不再混为一谈 ——
提升时只清 `parent_fingerprint`、保留 `reply_level`。那会改变 `/posts` 对外返回的
`reply_level`，属于**外部可见行为变更**，而且 `test_core.py:2552`、`:4709` 两条测试
明确钉住了「提成主贴时层级归 0」这个既定决策。按 fix 流程的升格判据，这该由用户拍板，
不在发版前私自改。

**这次做了的缓解**：S1 修好之后，「因别名漂移而产生的新孤儿」这条主要来源被堵住了；
存量的那两条无法追溯（父贴身份确实不可知）。
